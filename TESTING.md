# Testing

Xacqora Track ships a **vitest** suite of 83 tests across 7 files. The rule
from the spec (section 8): *"Every webhook handler gets a saved sample payload
and a test that replays it."* That's exactly what `test/adapters.test.ts`
does for all 14 platforms, and `test/ingest.test.ts` runs a real pipeline
against a throwaway SQLite DB.

## Run

```bash
pnpm test              # one-shot (vitest run)
pnpm test:watch        # watch mode
```

Each DB-backed test file opens its **own temp SQLite file** (via
`test/helpers.ts`) so `pnpm test` is safe to run in parallel and never touches
`prisma/dev.db`.

## Coverage by module

| File | What it proves |
|---|---|
| `test/identity.test.ts` | E.164 phone normalisation, email lowercasing, phone-first match, never-merge-across-clients, duplicate-candidate detection |
| `test/attribution.test.ts` | All 4 models, windowed vs. out-of-window, "Organic/unknown" fallback, click-count helpers, ad/adset/campaign/organic roll-up |
| `test/capi.test.ts` | SHA-256 phone/email hashing (E.164 without `+`), stable dedup keys, refund guard, match-quality scoring |
| `test/fx.test.ts` | Native→INR conversion on the stored daily rate, no live-rate drift |
| `test/adapters.test.ts` | Replays each platform's **saved sample** through `parse()`; verifies Razorpay HMAC + shared-secret paths |
| `test/ingest.test.ts` | **e2e**: fresh Meta lead → lead+event+queued CAPI; Razorpay payment → matches lead, records sale, advances stage; dedup on gateway txn; refund → skipped Refund note; source-unknown payment; signature rejection; webhook logging |
| `test/reports.test.ts` | Every report returns real numbers off the seeded demo DB |

## Pilot accuracy checks (spec tab H)

Before each gate, run these against a pilot client for one month:

- [ ] **Revenue match:** Xacqora Track's net revenue equals the payment
      gateway dashboards within **2 %**.
- [ ] **Spend match:** Xacqora Track spend per ad account equals Meta Ads
      Manager within **1 %**.
- [ ] **Attribution coverage:** ≥ 95 % of sales are tied to a specific ad
      (the rest bucketed under "Organic / unknown").
- [ ] **CAPI match quality:** Purchase events report Event Match Quality ≥ 7
      (target), verified on the Meta CAPI panel.
- [ ] **Latency:** every webhook lands on the right lead within 1 minute
      (check `WebhookLog.receivedAt` vs. `processedAt`).
- [ ] **No double-counting:** the same gateway transaction id can never
      produce two `Payment` rows (the unique `[gateway, gatewayTxnId]`
      index enforces this).

## Faking it safely

- No real client data, no real tokens, ever (spec rule 8).
- `META_ACCESS_TOKEN` empty → Meta pull + CAPI send run in
  **deterministic simulation** mode, so the whole flow works offline.
- The demo dataset is generated by `pnpm db:seed` — wipe + re-seed any time
  you need a clean slate.
